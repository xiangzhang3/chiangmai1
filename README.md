# CHIANGMAI1

结合用户提供的信息与催化剂，以及公开行情、OI、成交量和盘口，快速形成自己的交易判断，用独立模拟账户验证扣除成本后的表现。

状态核对：2026-10-10 UTC。恢复工作位于 `paper-recovery-2026-10-10`，见 [Draft PR #1](https://github.com/xiangzhang3/chiangmai1/pull/1)；尚未合并到 `main`。

## 1. 项目目标

- 把市场观察转成可复现、有版本的入场、退出和风险规则。
- 对齐周期价格变化、OI 变化及量能，比较小时量与历史小时基线、日量与历史日均量，再给出做多、做空或等待的判断。
- 先验证数据、再模拟成交，按策略分别记录手续费、滑点、资金费和净收益。
- 用样本外结果判断策略是否值得继续。当前没有足够交易样本，也没有盈利结论。

本项目当前仅做公开市场研究和 paper trading，不接实盘账户或真实下单接口。

## 2. 工作流程

1. 接收用户线索和催化剂，记录来源、事件时间与事实/推断；采集官方行情作交叉核验。
2. 对齐价格、数量 OI、成交量、主动买卖、资金费及盘口；校验合约、周期、新鲜度与缺失区间，不通过则 `ABSTAIN`。
3. 快速给出做多/做空/等待、触发条件、仓位、止损、失效条件、置信程度与数据完整性，再按明确策略版本判断信号。
4. 对已核验的模拟账户做仓位和成本检查，再模拟成交。
5. 单一写入者保存账本与证据，并回读远端确认。
6. 累积独立样本，复盘净收益、回撤和失效条件。

这是一份目标流程：用户信息融合、标准化判断输出及完整小时/日量基线比较尚待接入。当前规则覆盖 KAIA 恢复版做多和 JCT 新前瞻性做多试验；做空判断不能直接形成模拟单。消息本身不构成下单授权，模拟成交仍需通过账户、规则、数据和风险检查。

原计划是全市场雷达每 2 小时扫描、重点标的每小时观察。目前仅留存 KAIA/JCT 的官方网页样本；STRK 是待采集标的，全市场扫描和持续模拟执行均未完成验证。

## 4. 已核验的实现状态

- 恢复引擎已通过离线测试，数量及审查状态见 [RECOVERY_STATUS.json](v1.0/RECOVERY_STATUS.json)；测试使用合成数据，不访问交易所。网页 shadow 独立验证，不具备执行资格。
- 尚未取得一套完整、可执行的 Binance API 行情输入；官方网页采样只供研究。
- KAIA-A01 保留原始模拟检查点：1,000 USDT、空仓、零历史成交。JCT-A01 保留历史状态未知；新建的 JCT-P01-20261010 独立从 1,000 USDT 模拟资金开始，不承接或补造旧业绩。
- 当前没有新增模拟成交，也没有通过端到端验收的持续账户写入者。观察任务的排程不等于交易引擎已经恢复运行。
- Freqtrade、VectorBT、CVD/BTC 环境模块、网页看板和完整样本外评估尚未接入或完成。

代码和运行说明见 [v1.0/README.md](v1.0/README.md)，持久化约束见 [v1.0/OPERATIONS.md](v1.0/OPERATIONS.md)。本地只读检查：

```sh
cd v1.0
python -m unittest discover -s tests -v
python -m qingmai
```

需要 Python 3.10+；恢复入口仅使用标准库。最后一条命令尝试读取新行情，不写账本；数据不可用时应报告阻塞。

## 5. 绩效指标

按“账户 + 策略版本 + 观察区间”独立记录：净收益、已平仓净损益、胜率、Profit Factor、采样最大回撤、持仓时间、连续亏损、手续费、资金费和滑点。

零平仓样本的胜率与 Profit Factor 为 `null`；未知账户不计算收益。测试通过、研究标签命中和网页观察均不算交易业绩。指标口径见 [PERFORMANCE.md](PERFORMANCE.md)。

## 6. 下一步与验收

1. 核验每小时公开观察的实际采集、存储与回读；缺失小时如实记录。
2. 完成网页 shadow 候选审查，明确可支持的数据与仍缺的证据。
3. 打通完整行情和单一账本写入链路后，验收一次真实新数据驱动的模拟运行；无信号时允许零成交。
4. 用新 JCT 独立账户开展前瞻性试验，保留旧 JCT 未知状态；不补造交易。
5. 固定策略版本与评估方案，积累样本后再判断净盈利能力。

详细顺序见 [ROADMAP.md](ROADMAP.md)，数据口径见 [DATA.md](DATA.md)，风险与停止条件见 [RISK.md](RISK.md)。
